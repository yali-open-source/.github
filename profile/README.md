## YALI

**YALI Open Source** is an open technology organization focused on building,
sharing, and exploring software, tools, infrastructure, and creative
technology in the open.

We believe powerful technology should not only be built — it should be
understood, improved, shared, and made accessible to the people who want
to build with it.

Our work brings together:

- Open-source software
- Developer tools
- Artificial intelligence
- Automation
- Creative technology
- Developer infrastructure
- Experimental projects
- Community-driven innovation

> **Open Technology.  
> Open Creativity.  
> Open Future.**

---

## 🦁 Why YALI?

The YALI identity is inspired by the **Yali**, a mythical guardian-like
creature traditionally associated with strength, protection, and power.

Our lion represents the same philosophy in a modern technological form:

**Strength.  
Precision.  
Protection.  
Curiosity.  
Creation.**

The YALI identity combines traditional symbolism with modern engineering
and open-source culture.

# Mission

Our mission is simple:

> **Build useful technology. Open the process. Share what we learn.**

We want to create an environment where developers, designers, researchers,
students, makers, and technology enthusiasts can experiment and contribute
to meaningful projects.

YALI is built around the idea that open collaboration can produce technology
that is more transparent, adaptable, and accessible.

# Project Philosophy

Every YALI project should aim to follow a few principles.

### 01 — Build

Ideas are valuable, but working software is better.

We encourage experimentation and implementation.

### 02 — Open

Whenever practical, our work should be inspectable, reusable, and
contributable.

### 03 — Learn

Experiments don't always succeed.

Failure is part of engineering.

### 04 — Share

Useful knowledge should travel.

Documentation, examples, and lessons learned matter.

### 05 — Improve

Projects should evolve through feedback and contribution.

# Getting Started

If you are new to YALI, start by exploring our repositories.

### Step 1

Find a project that interests you.

### Step 2

Read its `README.md`.

### Step 3

Check the project's:

- Issues
- Discussions
- Documentation
- Contribution guidelines

Run the project locally.

### Step 5

Open an issue if you find a problem or have an idea.

### Step 6

Contribute when you're ready.

# Contributing

We welcome contributions of different kinds.

You can contribute by:

- Writing code
- Fixing bugs
- Improving documentation
- Designing interfaces
- Writing examples
- Testing projects
- Reporting issues
- Reviewing pull requests
- Suggesting ideas
- Improving developer experience

You don't have to make a huge contribution.

A small improvement can still make a project better for everyone.

---

## Before Contributing

Please check the repository-specific contribution guide before opening a
pull request.

If a repository does not yet have one, follow these general principles:

1. Keep changes focused.
2. Write clear commit messages.
3. Explain what your change does.
4. Test your changes.
5. Update documentation when necessary.
6. Be respectful to other contributors.
7. Keep discussions constructive.

---

# Pull Requests

A good pull request should explain:

### What changed?

Describe the implementation.

### Why?

Explain the problem or motivation.

### How?

Briefly describe the technical approach.

### Testing

Explain how the change was tested.
